สรุปเมื่อมีอะไรพัง

เกิดอะไรขึ้น ระบบทำอะไรเอง และคนต้องทำอะไรต่อ

หลักที่ระบบใช้

  • At-least-once: consumer commit offset หลัง handler ทำเสร็จ (EnableAutoCommit = false) ถ้าดับก่อน commit งานจะกลับมาให้ทำซ้ำ
  • Idempotent receiver: Source ใช้ ON CONFLICT (file_job_id, row_number) DO NOTHING, Normalized ใช้ upsert ตาม source_row_id และ handler ข้าม row job ที่อยู่ในสถานะสุดท้ายแล้ว
  • หนึ่งแถว หนึ่ง transaction: Source row + row job + outbox commit พร้อมกัน ดับกลางทางจึงไม่มีแถวที่บันทึกครึ่งเดียว

สถานการณ์

เกิดอะไรขึ้นระบบทำเองคนทำต่อ
Worker ดับกลาง importmessage ยังไม่ commit จึงได้รับซ้ำ handler เริ่มใหม่ตั้งแต่ขั้นหน่วง ข้ามแถวที่มีแล้วไม่ต้องทำ
Worker ดับกลาง normalizetransaction ย้อนกลับ row job ยัง Pending ได้ message ซ้ำแล้วทำใหม่ไม่ต้องทำ
Kafka ล่มWatcher ยังสร้างงานได้ message ค้างใน outbox (sent_at เป็น null) OutboxDispatcher ลองส่งใหม่ทุก 500 msไม่ต้องทำ
ข้อมูลในแถวผิดกฎrow job เป็น Invalid + Row Error ไม่ retryแก้ไฟล์ต้นทาง หรือสร้าง config version ใหม่แล้ว Reprocess
normalize พังชั่วคราวretry ใน handler หลัง 1, 2, 4 วินาที ครบ 4 รอบแล้วเป็น Failedแก้สาเหตุ แล้ว POST /row-jobs/{id}/retry
import ล้ม (header ไม่ครบ, exception)file job เป็น ImportFailed + lastErrorถ้าสาเหตุมาจากระบบ POST /file-jobs/{id}/retry (อ่าน snapshot เดิม จึงไม่ช่วยถ้าไฟล์ผิด)
ย้ายไฟล์ไป archive ไม่ได้ (IO error)ลองใหม่ทุก 1 วินาที รวม 3 รอบ แล้วเป็น ArchiveFailedดู lastError แก้สิทธิ์หรือพื้นที่ดิสก์
ไฟล์ต้นฉบับถูกแก้หลังระบบอ่านไปแล้วhash ไม่ตรงกับ snapshot จึงไม่ย้ายไฟล์ ตั้ง ChangedAfterRead และเก็บทั้งไฟล์ต้นฉบับกับ snapshot ไว้ตรวจว่าไฟล์ไหนถูกต้อง

Retry กับ Reprocess

RetryReprocess
ใช้เมื่อระบบพัง ข้อมูลและกฎถูกแล้วอยากใช้กฎ normalize รุ่นอื่น
งานที่รับImportFailed (file) หรือ Failed (row)ทุกแถวใน Source ของไฟล์
config versionรุ่นเดิมเลือกได้
row jobใช้ตัวเดิม กลับเป็น Pending, attempts = 0สร้างใหม่ kind = Reprocess
endpointPOST /file-jobs/{id}/retry
POST /row-jobs/{id}/retry		POST /file-jobs/{id}/reprocess body {"versionId": N}

แถวที่ reprocess ไม่ผ่าน ยังเก็บผล normalize ที่สำเร็จล่าสุดไว้ (Current Normalized Result) ส่วนการตั้งค่าจำลองความล้มเหลวมี Demo:FailImportAtRow และ Demo:FailNormalizeRowNumbers:0=N ดูขั้นตอนเต็มใน acceptance-test-guide.md
