# ตารางเลือกปลายทางและ Preview แบบ sticky

## คำขอและขอบเขต

ผู้ใช้ 2026-11-25 ขอเปลี่ยนช่อง `ปลายทาง` เป็น data table ที่ค้นหา เลือกใช้ และเปิดแก้ไขโปรไฟล์ได้ พร้อมแสดงรายละเอียดปลายทาง แบ่งฝั่งตั้งค่า/Preview เป็น 60/40 และให้ Preview อยู่บนหน้าจอขณะเลื่อน ตาม D-85 ปลายทางคือ contract + ช่องทางเชื่อมต่อ + path; ลิงก์แก้ไขจึงใช้หน้าเดิม `/mapping/contracts/edit?version=<name>` ซึ่งรับชื่อ contract ผ่าน query parameter ไม่ใช้หน้า Mapping Profile ของชุดงาน

## โครงหน้าจอที่เสนอ

```text
ฝั่งตั้งค่า 60%                         Preview 40% (sticky)
┌ ชนิดปลายทาง ───────────────────┐      ┌ Preview ───────────────┐
│ การ์ด 3 ชนิดแบบรูปแบบไฟล์      │      │ ปุ่มทดลอง + ผลสรุป    │
│ ตารางปลายทางอยู่ถัดลงมา         │      │ ผล JSON / ข้อความตรวจ │
│ ค้นหา / โหลดรายการใหม่ / สร้าง │      │ เลื่อนภายในเมื่อยาว   │
│ เลือกใช้ · รายละเอียด · แก้ไข   │      └──────────────────────┘
└─────────────────────────────────┘
┌ จับคู่ข้อมูลปลายทาง ────────────┐
│ เงื่อนไขแถว / รายการ / mapping │
└─────────────────────────────────┘
```

- ฝั่งซ้ายรวมการเลือกชนิด ตารางปลายทาง และการจับคู่ข้อมูลในแนวตั้ง; Preview เริ่มฝั่งขวาระดับเดียวกับการตั้งค่าปลายทางและคงสัดส่วน 3:2 ภายในพื้นที่หน้า ไม่รวม sidebar
- ใช้ PrimeNG Table ตาม D-78; ค้นหาชื่อ ช่องทาง และ path, เรียง/แบ่งหน้า และเห็นรายการที่เลือกชัดเจน; ปุ่ม `เลือกใช้งาน` ต้องใช้งานด้วย keyboard ได้
- ตารางแสดงชื่อปลายทาง, ช่องทาง (`connectionKey`), `POST` + path, รุ่นล่าสุด, จำนวนช่องข้อมูล, สถานะ และปุ่มแก้ไข; จัดรายละเอียดหลายบรรทัดเพื่อลดความกว้างตารางในพื้นที่ 60%
- ปุ่ม `แก้ไขโปรไฟล์ปลายทาง` เปิดหน้าแก้ไขเดิมในแท็บใหม่ เพื่อคงค่าที่จับคู่ในแท็บนี้; กลับมาแล้วกดโหลดรายการใหม่และเลือกใช้รุ่นล่าสุดได้ โดยคงค่าของ path ที่ยังตรงกันตามพฤติกรรมเดิม
- ปลายทางใช้ไม่ได้ยังเห็นรายละเอียดและลิงก์แก้ไข แต่เลือกใช้ไม่ได้; แยกสถานะกำลังโหลด/โหลดผิดพลาด/ยังไม่มีรายการ/ค้นหาไม่พบ
- การค้นหาและเปลี่ยนหน้าตารางไม่เปลี่ยนปลายทางที่เลือก; รายละเอียดของรายการที่เลือกต้องยังตรวจดูได้เมื่อถูกกรองออกจากตาราง
- Preview ใช้ `position: sticky` กับ scroll container `.main` เดิม มีระยะด้านบน และจำกัดความสูงตาม viewport พร้อมเลื่อนผลด้านใน เพื่อให้ปุ่ม Preview ยังเข้าถึงได้; ไม่แก้ sticky behavior ของหน้าอื่น
- เก็บ `data-tour` ที่ใช้อยู่และปรับคำอธิบาย tour ให้ตรงกับตารางและ Preview ใหม่

## ตัวอย่างข้อมูลสมมติ

| ชื่อ | ช่องทาง / วิธีส่ง | รุ่น / จำนวนช่อง | การใช้งาน |
|---|---|---|---|
| sample-inform | sample-api · POST /api/sample/informs | รุ่น 2 · 12 ช่อง | เลือกใช้งาน / แก้ไข |
| sample-archive | archive-api · POST /api/sample/archive | รุ่น 1 · 8 ช่อง | ใช้ไม่ได้ / แก้ไข |

ค้นหา `archive` → เหลือแถว `sample-archive`; ถ้าเลือก `sample-inform` อยู่ก่อน การค้นหาไม่เปลี่ยนค่าที่เลือก เปิดแก้ไข `sample-inform` → `/mapping/contracts/edit?version=sample-inform` ในแท็บใหม่ หลังบันทึกรุ่น 3 กลับมาโหลดรายการใหม่และเลือกใช้รุ่นล่าสุด → โหลด schema รุ่น 3 และเก็บ mapping ของ path ที่ยังตรงกัน

## ไฟล์ที่ผู้ใช้ยืนยันให้แก้

Repo Web:

- `src/app/features/mapping/mapping-new.html` — ตารางค้นหา/เลือก/ลิงก์แก้ไข/รายละเอียด และโครงฝั่งซ้ายกับ Preview
- `src/app/features/mapping/mapping-new.ts` — state ค้นหาและโหลดข้อมูลซ้ำ รวมการเลือก contract revision ล่าสุดโดยรักษาค่าของ path เดิม
- `src/app/features/mapping/mapping-new.spec.ts` — ตรวจ logic ที่เกี่ยวกับการเลือก/โหลดข้อมูลล่าสุดตามความจำเป็น
- `src/app/features/mapping/mapping-new-tour.ts` — ข้อความวิธีใช้ตารางและ sticky Preview
- `src/styles.scss` — styles เฉพาะ Mapping สำหรับสัดส่วน 60/40 และ sticky Preview/การเลื่อนภายใน

ตรวจรับด้วย production build, Web tests และ browser QA ที่ 1280/1440 px: ค้นหา/เลือก/แก้ไข link ถูกหน้า, คงค่าที่เลือกเมื่อค้นหา, รับรุ่นล่าสุดหลังโหลดใหม่, empty/error states และเลื่อนจริงเพื่อยืนยัน sticky/ความสูง Preview โดยไม่ส่งข้อมูลไปปลายทาง

## ผลหลังผู้ใช้ยืนยัน (2026-11-25, M-43)

- ทำตารางปลายทางใต้การ์ดชนิดปลายทางแล้ว มีการค้นหาชื่อ/ช่องทาง/path, เรียงชื่อ, แบ่งหน้า 10/20/50, สถานะ, ปุ่มเลือกใช้ และลิงก์แก้ไขโปรไฟล์ปลายทางในแท็บใหม่; แสดงข้อมูลรุ่นที่เลือกแยกไว้แม้ค้นหาแล้วไม่พบแถวนั้น
- ปุ่ม `โหลดรายการใหม่` โหลด catalog และ destination profiles ใหม่ โดยไม่แทน schema/โปรแกรมที่เลือก; ถ้ามี revision ใหม่ให้กด `ใช้รุ่นล่าสุด` ก่อน จึงโหลด schema และจับคู่ profile ใหม่ โดยคงค่าของ path ที่ชื่อตรงกันและล้างผล Preview เก่าหลังเปลี่ยนปลายทางสำเร็จ
- กรณีโหลดรายการไม่สำเร็จแสดงข้อความผิดพลาดและลองใหม่ได้ ไม่ล้างค่าที่จับคู่; ปุ่มเลือกใช้ถูกปิดขณะโหลด/ข้อมูลพร้อมใช้ไม่ได้ เพื่อไม่เลือกข้อมูลที่โหลดไม่ครบ
- จัดฝั่งตั้งค่า 60%/Preview 40% แล้ว; Preview sticky ที่ top 16 px ภายใน `.main`, จำกัดความสูง `calc(100dvh - 110px)` พร้อมเลื่อนผลด้านใน
- หลักฐาน: `npm run build` ผ่าน; `npm run test:ci` **111/111 ใน 12 suites** รวม 6 ข้อใหม่ของการค้นหา/reload/เลือก revision; `git diff --check` ผ่าน
- Edge headless QA ใช้ข้อมูลสมมติใน browser: ค้นหา/ไม่พบรายการ/รายละเอียดที่เลือกยังอยู่, ลิงก์แก้ไขพร้อม query/แท็บใหม่, ปลายทางใช้ไม่ได้เลือกไม่ได้, reload เห็นรายการใหม่โดยคง mapping, reload error/retry, เลือกรุ่นล่าสุดเองและคงค่า path เดิม, เปลี่ยนปลายทาง และมี pagination ผ่าน; ไม่พบ runtime exception หรือคำขอเขียน Mapping API
- ผลวัด layout: 1440 px ได้ 663/442 px และ 1280 px ได้ 567/378 px เป็น 3:2 พอดี ไม่มี page overflow; เลื่อน `.main` 500 px แล้ว Preview อยู่ top 16 px, สูงไม่เกิน 890 px บน viewport สูง 1000 px และ body มี scroll ภายใน
- รอบนี้ตรวจ UI/logic และ mock ข้อมูลสำหรับ browser เท่านั้น ไม่สร้าง/แก้ปลายทางจริง ไม่ใช่หลักฐาน Preview API ด้วยไฟล์จริงหรือ external delivery E2E; รุ่นสุดท้ายรวม M-44–M-45 ใน Web `e6349e4` (โค้ด) + `a85f618` (styles) และ push ขึ้น `origin/develop` แล้ว
