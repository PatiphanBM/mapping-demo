# หน้าเว็บ mapping — หลักร่วม

> หน้าเว็บ mapping อยู่ใน repo **`prjInsuranceValidationWeb`** เดียวกับเมนูใบคำขอ (UW) และ Config ของ Dev 1 (D-78) · ไฟล์นี้คัดจาก PRD หน้าเว็บของ Dev 1 (`insurance-validation/03-prd/web/frontend-prd.md` §2–§4, ฉบับ 2026-11-10) + กฎของ repo Web — เพื่อให้หน้า mapping หน้าตาและพฤติกรรมเหมือนเมนูอื่น
> **ขอบเขตของหน้า mapping (หน้าไหน ทำอะไรได้) ยังไม่ตกลง** — คำถามข้อ 8 ใน [rules.md](rules.md) §6 · Dev 2 ออกแบบเป็นไฟล์ในโฟลเดอร์นี้หลัง kickoff

## 1. ผู้ใช้และสภาพแวดล้อม

- เว็บภายในบริษัท ใช้บนจอ desktop / notebook (ไม่ต้องรองรับ mobile)
- **Angular 21 + PrimeNG 21** — ใช้ component ที่ PrimeNG มี · **ห้ามขึ้น PrimeNG 22+ / Angular 22** (license — D-78)
- ภาษาบนหน้าจอ: ไทย · code ของระบบ (status, message code, product code, partner code) แสดงตามจริงเป็นอังกฤษ
- **ยังไม่มี login** — phase นี้ใช้ผู้ใช้คงที่ ไม่มีสิทธิ์แยก · header มีที่วางชื่อผู้ใช้ไว้เผื่ออนาคต
- ผู้ใช้ของหน้า mapping (ร่าง): **Dev / DevSupport** ตั้งค่า mapping · ops / UW ดูผลการส่ง (แถวที่ส่งไม่สำเร็จ — D-36)
- **เมนูไม่เชื่อมกัน** (D-32): เมนูของแต่ละฝ่ายไม่ลิงก์ข้ามกัน — ถ้าหน้า mapping ต้องลิงก์ไปเมนูใบคำขอ (เช่น จากแถวที่ส่งสำเร็จไปที่ใบ) ให้เสนอใน `plan.md` ก่อน

## 2. โครงเมนูตอนนี้

```
[header: ชื่อระบบ · เมนู · ชื่อผู้ใช้]

เมนู "ใบคำขอ" (UW)                    features/uw/       Dev 1
เมนู "Product config" (เมนูย่อยพับได้)   features/config/   Dev 1
เมนู "Product Master" (เมนูย่อยพับได้)   features/config/   Dev 1
เมนู "Mapping"                         features/mapping/  Dev 2  ← ยังไม่มี
```

- เมนูที่มีหลายหน้าใช้ **หัวข้อพับ / กางได้ + เมนูย่อย 1 ตัวต่อหน้า** (กางไว้เป็นค่าเริ่มต้น)
- หน้ารายการ (ตาราง) ของเมนูอื่นใช้รูปแบบเดียวกัน: แถวบน = ช่องค้นหา + ตัวกรองต่อคอลัมน์ + ล้างตัวกรอง · ชิดขวา = จำนวนรายการ + ปุ่ม "เพิ่ม …" · ตารางเรียงตามคอลัมน์ + แบ่งหน้า 10 / 20 / 50 — หน้ารายการของ mapping ควรทำแบบเดียวกัน (ดูโค้ดใน `features/config/` เป็นตัวอย่าง)

## 3. หลักร่วมทุกหน้า

| เรื่อง | กติกา |
|---|---|
| รูปแบบวันที่ | **แสดงเป็น `dd-mm-yyyy`** (เวลาต่อท้าย `06-11-2026 11:14`) · **ช่องวันที่ทุกช่องเป็น date picker** (พิมพ์ `dd-mm-yyyy` ได้) · ข้อมูล / API ยังเป็น ISO `yyyy-mm-dd` · เวลาแสดงเวลาไทย |
| บันทึกทั้งก้อน | ฟอร์มส่งค่าทั้งหน้าในครั้งเดียว ไม่บันทึกทีละช่อง · มีปุ่มยกเลิกการแก้ = ทิ้งค่าบนหน้าจอ |
| มีคนบันทึกก่อน (`409`) | ใช้ตัวนับ version · ถ้ามีคนบันทึกระหว่างที่เราแก้ → บันทึกไม่ได้ แจ้งชัดว่า "มีคนแก้ไปก่อน — โหลดใหม่" โดย**ไม่ทิ้งค่าที่พิมพ์ไว้ทันที** |
| error ของช่อง (`400`) | API บอกชื่อ field ที่ผิด → แสดงข้อความข้างช่องนั้น |
| ไม่มีลบ | เมนูอื่นไม่มีปุ่มลบ (ปิดใช้แทน) — ถ้าหน้า mapping ต้องลบ ให้เสนอก่อน |
| loading | งานที่รอผลนาน ต้องมีสถานะกำลังทำ และกันกดซ้ำ |
| อ่านอย่างเดียว | ข้อมูลที่แก้ไม่ได้ต้องดูออกว่าแก้ไม่ได้ (ไม่ใช่ช่อง disabled เฉย ๆ โดยไม่มีเหตุผล) |
| ตัวเลขเงิน | 2 ตำแหน่ง มีคอมมา (`180.00`, `500,000`) |
| ค่าว่าง | ค่าที่ยังไม่ได้ตั้ง **ต้องเห็นชัดว่ายังไม่ได้ตั้ง** ไม่ใช่ดูเหมือนเป็น 0 |
| ข้อมูลตัวอย่าง | ข้อมูลสมมติเท่านั้น ห้ามใช้ข้อมูลลูกค้าจริง |

## 4. กฎของ repo Web (หลายคนทำ repo เดียวกัน)

> ฉบับเต็มอยู่ใน `CLAUDE.md` + `AGENTS.md` ของ repo Web — อ่านก่อนเขียนโค้ด

- **1 เมนู = 1 folder ใต้ `features/`** — หน้า mapping อยู่ `src/app/features/mapping/` เท่านั้น · ห้ามแก้ไฟล์ใน folder ของเมนูอื่นเพื่องานของตัวเอง · ของที่ใช้ร่วมย้ายไป `shared/` (component / pipe) หรือ `core/` (ตัวเรียก API / model)
- **ตัวเรียก API 1 ไฟล์ต่อ service ใน `core/`** — สร้าง `core/mapping-api.ts` แบบเดียวกับ `core/config-api.ts` (แกะ `BaseResponse` → `result` / `messages`, แปลง DTO เป็น model ของหน้าเว็บ) · base URL `mappingApiUrl` ใน `src/environments/environment.ts` · Mapping API = port 5177
- route ใหม่ใน `src/app/app.routes.ts` แบบ `loadComponent` (lazy) ใต้ `Shell` · เมนูใน `layout/shell.ts`
- แก้ไฟล์ร่วม (`app.routes.ts`, `shell.ts`, `environment.ts`, `models.ts`, `styles.scss`, `package.json`) ให้ commit แยกและสั้น จะได้ merge ง่าย
- **เพิ่ม package ใน `package.json` → บอก Dev 1 ก่อน** (กระทบ build ของทุกเมนู) · ห้าม `npm update` / `ng update` ข้าม major
