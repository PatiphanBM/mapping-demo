# ไฟล์ทดสอบ MTLS — ข้อมูลสมมติ ใช้แทนไฟล์จริงได้

> **ใช้ไฟล์นี้แทน `docs/MTLSPA0220261009.xls`** ไฟล์นั้นเป็นข้อมูลจริงของลูกค้า ห้ามใช้ใน test / commit / log
> ไฟล์นี้ Dev 1 สร้างให้วันที่ 2026-11-16 (ตอบ Q7 ใน [plan.md](../plan.md))

| ไฟล์ | คืออะไร |
|---|---|
| `MTLSPA0220261201.xls` | ไฟล์ทดสอบ 2,556 แถว ชื่อไฟล์ตามแบบ MTLS: `MTLSPA02` + `yyyymmdd` (= วันเริ่มคุ้มครอง) |
| `make-mtls-fixture.py` | script ที่ใช้สร้างไฟล์ · seed กับวันเริ่มเดิมจะได้ไฟล์เหมือนเดิมทุก byte |

สร้างใหม่ (ถ้าอยากได้วันเริ่มคุ้มครองอื่น):

```powershell
python -I make-mtls-fixture.py MTLSPA0220261215.xls --start 2026-12-15
```

## 1. อะไรเหมือนไฟล์จริง

ตัวเลขในตารางเลียนจากสถิติของไฟล์จริงตาม [mtls-file.md](../mtls-file.md) ส่วนข้อมูลรายคนเป็นของที่สร้างขึ้นทั้งหมด

| เรื่อง | ค่าในไฟล์นี้ |
|---|---|
| รูปแบบไฟล์ | **Excel 5.0/95 (BIFF5)** แบบเดียวกับไฟล์จริง: ใน OLE2 มี stream ชื่อ `Book`, sheet เดียวชื่อ `Test` |
| ภาษาไทย | CODEPAGE record บอกว่าเป็น **1252** แต่ข้อความจริงเป็น byte ของ **cp874** แบบเดียวกับไฟล์จริง reader จึงต้องบังคับใช้ cp874 ถ้าเปิดตาม codepage ในไฟล์ภาษาไทยจะเพี้ยน |
| header | แถวแรก 19 column ภาษาไทยตามลำดับเดิม (`ลำดับ` … `เวลาเริ่มคุ้มครอง`) |
| ชนิดของ cell | ตัวเลข: ลำดับ, เลขบัตร, วันที่ (`yyyymmdd`), รหัสสาขา, จำนวนเงิน, วันเกิด, อายุ · ข้อความ: ที่เหลือ · ช่องข้อความที่ว่างเป็นข้อความยาว 0 · เลขบัตรของแถว `C` เป็น cell ว่าง (BLANK) |
| จำนวนแถว | 2,556 แถว: `P` 2,553 แถว · `C` 3 แถว (ลำดับ 671, 672, 2542) · ลำดับ 1..2556 ต่อเนื่อง |
| คน | 1,797 คน: 1,041 คนมี 1 แถว · **756 คนมี 2 แถว** (ส่วนใหญ่อยู่ติดกัน บางคนแถวที่ 2 อยู่ห่างออกไป) · ไม่มีใครมีเกิน 2 แถว · 2 แถวของคนเดียวกันต่างกันแค่ลำดับ, หมายเลข PA, เวลา และบางแถวต่างที่ผู้รับผล |
| เลขบัตร | 13 หลักและผ่าน checksum ยกเว้น **2 แถวที่มีแค่ 11 หลัก** |
| หมายเลข PA | `PF` + 6 หลัก ไม่ซ้ำทั้งไฟล์ |
| วันที่ | `P`: เริ่ม `20261201` สิ้นสุด `20271130` · `C`: `-293` ทั้ง 2 ช่อง |
| จำนวนเงิน | `P` = 180 · `C` = 0 |
| อายุ | 20–65 ปี = ปีที่เริ่มคุ้มครอง − ปีเกิด ทุกแถว |
| ชื่อ | คำนำหน้า `นาย` / `นางสาว` / `นาง` ติดกับชื่อไม่มีช่องว่าง · 3 แถวมี 3 คำ |
| ที่อยู่ | ต่างจังหวัดใช้ `ม.` `ต.` `อ.` `จ.` · กรุงเทพฯ ใช้ `แขวง` `เขต` · ลงท้ายด้วยรหัสไปรษณีย์ 5 หลัก · 20 คนมีคำซ้ำ (แบบที่ legacy ใช้ `RemoveDupWords` ตัด) · แถว `C` ที่อยู่ว่าง |
| สาขา | 1,079 สาขา รหัส 3–4 หลัก รหัสกับชื่อเป็น 1:1 |
| ผู้รับผล | มีผู้รับผล 1 ทุกแถว · ผู้รับผล 2 มี 210 แถว · คำนำหน้าไม่สม่ำเสมอแบบไฟล์จริง (`น.ส.` / `นส.` / `ด.ญ.` / `เด็กชาย` / มีช่องว่างหลังคำนำหน้า / ไม่มีคำนำหน้า) |
| ความสัมพันธ์ / อาชีพ | ใช้รายการค่าที่เจอในไฟล์จริง (ความสัมพันธ์ 17 ค่า · อาชีพ 59 ค่า รวม `ทหาร` ที่ยาว 4 ตัวอักษร) |
| แถว `C` | ชื่อ `ยกเลิก` · ไม่มีเลขบัตร / ที่อยู่ · ยังมีหมายเลข PA, สาขา, วันเกิด, อายุ, ผู้รับผล, อาชีพ, เวลา |

## 2. อะไรไม่เหมือน (อย่าใช้ทดสอบเรื่องเหล่านี้)

- **ชื่อ, เลขบัตร, หมายเลข PA, บ้านเลขที่ เป็นของที่สร้างขึ้น** ชื่ออาจบังเอิญซ้ำกับคนจริงได้แต่ไม่ได้มาจากข้อมูลจริง
- **ชื่อสาขาเป็น `สาขาทดสอบ NNNN`** ไม่ใช่ชื่อสาขาจริง
- **ที่อยู่ใช้ชื่อตำบล / อำเภอ / จังหวัด / รหัสไปรษณีย์ที่มีจริง** (23 ชุดต่างจังหวัด + 12 ชุดกรุงเทพฯ) เพื่อให้มีอะไรให้ตัวแยกที่อยู่จับคู่ แต่ไม่ได้ครอบทุกจังหวัด และไม่มีชื่อตำบลซ้ำข้ามจังหวัด
- คำนำหน้าของผู้รับผลกับความสัมพันธ์สุ่มแยกกัน (อาจได้ `นางสาว…` + `สามี`) ไม่ต้องตรวจความสอดคล้องจากไฟล์นี้
- ทุกแถว `P` มีผู้รับผล 1 เหมือนไฟล์จริง ถ้าจะทดสอบการเติม "ทายาทตามกฎหมาย" (BR-035) ให้ลบชื่อผู้รับผลในสำเนาของไฟล์เอง

## 3. ผลที่คาดเมื่อส่งเข้า Insurance Validation

- แถว `P` 2,553 แถว → ใบงานใหม่ · แถว `C` 3 แถว → ใบ `CANCELLED` (หมายเลข PA ของแถว `C` ไม่ซ้ำกับแถว `P` ใด)
- stage PRODUCT: ผ่านทุกใบ ยกเว้นข้อที่ config ของ `MTLSPA` / `MTL2` ยังไม่ตั้ง (`*_NOT_CONFIGURED` เช่นทุน / plan code)
- เพดาน 2 ใบต่อคน: คนที่มี 2 แถวไม่เกินเพดาน
- เลขบัตร 11 หลัก 2 แถว: phase 1 ไม่ตรวจ checksum (ตัด `ID_NO_INVALID` แล้ว)
