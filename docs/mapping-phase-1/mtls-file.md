# ไฟล์ของ MTLS

> คัดจากการวิเคราะห์ไฟล์ตัวอย่างจริง `MTLSPA0220261009.xls` ของ Dev 1 (`insurance-validation/01-analysis/mtls-sample-file.md`, 2026-10-14) เฉพาะส่วนที่ mapping ใช้ · ตัวเลขเป็นสถิติ ไม่มีข้อมูลรายคน
> **ไฟล์จริงมีข้อมูลส่วนบุคคล** — พัฒนาและทดสอบด้วย**ไฟล์ทดสอบ 2,556 แถว (ข้อมูลสมมติ) ที่ Dev 1 ให้** เท่านั้น (D-70)
> ที่มาใน legacy: `uMTLS.pas` ของโปรแกรม CRC0001 (Delphi) — อ้างบรรทัดไว้ให้ตามได้ แต่ Dev 2 ไม่ต้องเปิด
> column → path ใน contract: [contract-pa-inform.md](contract-pa-inform.md) §3.1

## 1. ตัวไฟล์

| เรื่อง | ค่า | ผลต่อ mapping |
|---|---|---|
| รูปแบบ | Excel 97–2003 (`.xls`, BIFF8) **ไม่มี CODEPAGE record** | ต้องอ่านเป็น **cp874 (TIS-620)** ไม่งั้นภาษาไทยเพี้ยน → config ของไฟล์ต้องกำหนด encoding ได้ |
| ชื่อไฟล์ | `MTLSPA02` + `yyyymmdd` (= วันเริ่มคุ้มครอง) | |
| sheet | 1 sheet (ชื่อ `Test` ในไฟล์ตัวอย่าง) | อ่าน **sheet แรก** แบบ legacy ไม่อ้างชื่อ sheet |
| header | แถวที่ 1 ภาษาไทย 19 column | ลำดับตรงกับ legacy (`uMTLS.pas:515-535`) |
| จำนวนแถว | 2,556 (`P` 2,553 / `C` 3) | ลำดับ (column 1) 1..2556 ต่อเนื่อง ไม่ซ้ำ |
| 1 แถว | = ใบคำขอ 1 ใบ = ผู้เอาประกัน 1 คน (= ผู้ถือกรมธรรม์) · ผู้รับประโยชน์สูงสุด 2 คน | `insureds[]` มี 1 คน · `outputKey` = `"default"` |
| confirm / cancel | MTLS ไม่มีไฟล์ confirm / cancel | |

## 3. ผลต่อการแปลงค่า

| # | ข้อเท็จจริง | ต้องทำ |
|---|---|---|
| S1 | ไฟล์เป็น cp874 ไม่มี codepage | กำหนด encoding ใน config ของไฟล์ |
| S2 | เลขบัตรและวันที่เป็น **number** ใน Excel | แปลงเป็นข้อความ / วันที่**โดยไม่มีทศนิยม** (`.0`) · เลขบัตรที่สั้นกว่า 13 หลัก**ส่งตามที่ได้** ไม่เติม 0 เอง (เลขบัตรไทยไม่ขึ้นต้นด้วย 0) — การตรวจเป็นงานของ Informs / Client API |
| S3 | วันที่ `-293` ในแถว `C` | แปลงไม่ได้ → `null` + ค่าดิบใน `extras.unparsed.<field>` (D-04) **ไม่ทิ้งแถว** |
| S4 | แถว `C` ไม่มีชื่อ / เลขบัตร / ที่อยู่ / วันที่ (ชื่อ = `"ยกเลิก"`) | ส่งตามที่มี — Informs เก็บเป็นใบ `CANCELLED` ไม่ตรวจ (BR-010) |
| S5 | 1 คน (เลขบัตรเดียวกัน) มี 2 แถวในไฟล์เดียว: 756 คน | **ไม่ใช่แถวซ้ำ** — กันซ้ำด้วยหมายเลข PA เท่านั้น (BR-003) |
| S6 | ผู้รับผลไม่มีชื่อเลย | เติม 1 คน "ทายาทตามกฎหมาย" 100% (BR-035 — MTLS เท่านั้น) |
| S7 | ชื่อผู้รับผลไม่สม่ำเสมอ (`นางสาว` / `น.ส.` / `นส.` / `ด.ญ.` / `ด.ช.` / ไม่มีคำนำหน้า 452 แถว) | ส่งตามที่เป็น — Client API จัดการ |
| S8 | อาชีพ `ทหาร` ยาว 4 ตัว — legacy ถือว่า "≤ 4 ตัว = รหัส" แล้วใส่ผิดช่อง | **ห้ามใช้กฎความยาวแบบ legacy** · ส่งเป็นข้อความเสมอ (BR-041) |

## 4. แถว `C` (ยกเลิก)

- ชื่อ-สกุล = `"ยกเลิก"`, เลขบัตรว่าง, ที่อยู่ว่าง, วันเริ่ม / สิ้นสุด = `-293`, จำนวนเงิน = 0
- **ยังมี** หมายเลข PA, สาขา, วันเกิด, อายุ, ผู้รับผล, อาชีพ, เวลา
- หมายเลข PA ของแถว `C` ไม่ซ้ำกับแถว `P` ใดเลย → เป็น record ของเลข PA ที่ถูกยกเลิก (ฝั่ง partner ล้างข้อมูลระบุตัวตนออกแล้ว)
- ตัวอย่าง JSON ของแถว `C`: [contract-pa-inform.md](contract-pa-inform.md) §3.2
