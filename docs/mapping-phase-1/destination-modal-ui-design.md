# จัดการปลายทางใน modal

## เป้าหมายและที่มา

ผู้ใช้ 2026-11-25 ขอให้ส่วน `ส่งไปที่ไหน และกรอกทุก field ของปลายทาง` เป็น modal และให้หน้าจอหลักเหลือปุ่มจัดการปลายทาง เพื่อให้ใช้งานง่ายขึ้นจาก [ตารางปลายทาง M-43](destination-table-ui-design.md) และภาพที่แนบ; ใช้ PrimeNG Dialog/Table เดิมตาม D-78 และหน้าแก้ไขปลายทางเดิมตาม D-85

## หน้าหลัก

ฝั่งซ้าย 60% แสดงรายละเอียดปลายทางที่ใช้แบบย่อ ตามด้วยส่วนจับคู่ข้อมูล ส่วน Preview sticky ฝั่งขวา 40% คงเดิม:

```text
ปลายทางที่ใช้                          [จัดการปลายทาง]
sample-inform · รุ่น 2 · 12 ช่องข้อมูล   พร้อมใช้
sample-api · POST /api/sample/informs

จับคู่ข้อมูลปลายทาง                    Preview sticky
เงื่อนไข / รายการ / ช่องข้อมูล          ทดลองและดูผล
```

ถ้ายังไม่ได้เลือก แสดง `ยังไม่ได้เลือกปลายทาง` พร้อมปุ่มจัดการปลายทางที่เห็นชัดเจน ไม่แสดงการ์ดชนิดหรือตาราง catalog ทั้งชุดบนหน้าหลัก; รายละเอียดที่ใช้แสดงคือรุ่นที่โหลดแล้ว ไม่ใช่ metadata ของรุ่นล่าสุดใน catalog

## Modal: จัดการปลายทาง

- หัวข้อ `จัดการปลายทาง` พร้อมข้อความสั้น `เลือกปลายทางที่จะใช้กับ Mapping นี้`
- ภายในมีการ์ดชนิดปลายทาง 3 ใบแบบรูปแบบไฟล์ แล้วเป็นตารางเดิมที่ค้นหาชื่อ/ช่องทาง/path ได้ มีรายละเอียด รุ่น จำนวนช่อง สถานะ เรียงและแบ่งหน้า
- ปุ่ม `สร้างปลายทาง` เปิดแท็บใหม่; ปุ่ม `โหลดรายการใหม่` อยู่หัวตารางเพื่อเห็นรายการเพิ่ม/แก้ไขใหม่; ปุ่ม `แก้ไขโปรไฟล์` ในแต่ละแถวเปิด `/mapping/contracts/edit?version=<name>` ในแท็บใหม่ตามเดิม
- ความกว้างรองรับตารางบน notebook/desktop (ประมาณ 1100 px และไม่เกิน 95vw); จำกัดความสูงตาม viewport และเลื่อนเนื้อหาภายใน โดย footer ใช้งานได้เสมอ
- เลือกแถวแล้วแสดง `เลือกไว้` พร้อมสรุปชื่อ/รุ่นที่กำลังเลือก แยกจากปลายทางที่กำลังใช้จริง; ใช้ปุ่มหรือ radio ที่ใช้งานด้วย keyboard ได้
- Footer มี `ยกเลิก` และ `ใช้ปลายทางนี้` ปุ่มใช้ได้เมื่อรายการพร้อมใช้งานและไม่ได้กำลังโหลด

## พฤติกรรมการเลือก

1. กดจัดการปลายทาง → เปิด modal พร้อมเลือกแถวของปลายทางที่ใช้ไว้เบื้องต้น ไม่เปลี่ยน schema/การจับคู่/Preview
2. ค้นหา เปลี่ยนหน้า เลือกแถว หรือโหลดรายการใหม่ → เปลี่ยนเฉพาะ catalog/สิ่งที่เลือกไว้ใน modal ยังไม่ใช้ schema ใหม่ทันที
3. `ยกเลิก`/ปุ่มปิด/Escape → ทิ้งสิ่งที่เลือกไว้และคงปลายทาง การจับคู่ และ Preview ที่ใช้ก่อนเปิด; ปิดด้วย backdrop ไม่ทิ้งสิ่งที่กำลังเลือกโดยไม่ตั้งใจ
4. `ใช้ปลายทางนี้` → โหลดรายละเอียดรุ่นล่าสุดตามรายการ ตรวจสำเร็จแล้วใช้ปลายทาง ผูก profile ให้ตรงรุ่น คงค่าของ path ที่ตรงกัน และล้าง Preview เก่าเมื่อเปลี่ยนสำเร็จตาม M-43; แจ้ง path ที่ย้ายไม่ได้ด้วยกลไกเดิม
5. โหลดรายละเอียดไม่สำเร็จ → modal ยังเปิดพร้อมข้อความให้ลองใหม่ ไม่ทิ้งค่าการจับคู่เดิม; ระหว่างยืนยันมี loading และกันกดซ้ำ/ปิดคั่นกลาง
6. เปิด modal ใหม่ → เริ่มจากปลายทางที่ใช้จริง ไม่จำสิ่งที่ยกเลิกไป; คืน focus ให้ปุ่มจัดการปลายทางเมื่อปิด

**ตัวอย่างสมมติ:** กำลังใช้ `sample-inform` รุ่น 2 → เปิด modal และเลือก `sample-archive` → ยกเลิก → ยังใช้ `sample-inform` รุ่น 2 และ Preview เดิม; เปิดอีกครั้งแล้วเลือก `sample-archive` และกดใช้ → เปลี่ยนเมื่อโหลด schema สำเร็จเท่านั้น

กรณีโหลดรายการใหม่แล้ว `sample-inform` มีรุ่น 3 ให้เห็นรุ่นใหม่ใน modal แต่หน้าหลักยังใช้รุ่น 2 จนกดยืนยัน; การ refresh profiles ต้องไม่ทำให้ snapshot ที่ใช้อยู่หายไปก่อนตัดสินใจ

## ไฟล์ที่ผู้ใช้ยืนยันให้แก้

Repo Web:

- `src/app/features/mapping/mapping-new.html` — ย่อส่วนปลายทางบนหน้าหลัก ย้ายการ์ดและตารางเข้า Dialog เพิ่มปุ่มเปิด/ยกเลิก/ยืนยัน
- `src/app/features/mapping/mapping-new.ts` — แยกสิ่งที่เลือกไว้ใน modal จากสิ่งที่ใช้จริง พร้อมการยืนยัน/ยกเลิก/loading/error และคง snapshot ขณะ reload
- `src/app/features/mapping/mapping-new.spec.ts` — ตรวจเลือกแล้วยกเลิก, reload ไม่เปลี่ยนของเดิม, ยืนยันสำเร็จ/ล้มเหลว และเปิดใหม่ไม่จำสิ่งที่ยกเลิก
- `src/app/features/mapping/mapping-new-tour.ts` — ชี้ปุ่มจัดการปลายทางและอธิบายการใช้ modal โดยคง selector ของ tour ที่มีอยู่บนหน้าหลัก
- `src/styles.scss` — styles เฉพาะ Mapping ของรายละเอียดแบบย่อ/ตารางใน Dialog/พื้นที่ scroll โดยคง sticky Preview 60/40

ตรวจด้วย Web build/tests และ browser QA ที่ 1280/1440 px รวมเปิด/ปิด/ยกเลิก/ยืนยัน, focus/keyboard, ค้นหา/reload/ลิงก์แก้ไข, การรักษาค่าเมื่อโหลดล้มเหลว และ sticky Preview หลังย้ายตาราง

## ผลหลังผู้ใช้ยืนยัน (2026-11-25, M-44)

- ทำหน้าหลักแบบย่อพร้อมปุ่ม `จัดการปลายทาง` แล้ว; การ์ดชนิดและตารางอยู่ใน PrimeNG Dialog ขนาดไม่เกิน 1100 px/95vw และสูงไม่เกิน 90dvh ตารางเลื่อนภายในที่ 320 px พร้อม footer นอกส่วนเนื้อหาที่เลื่อน
- แยก pending selection ใน modal จาก contract/profile ที่ใช้อยู่; การค้นหา เลือกแถว และ reload ไม่เปลี่ยนการจับคู่หรือ Preview; เก็บ applied profile snapshot ไว้เมื่อ refresh catalog ส่งกลับเฉพาะรุ่นใหม่
- ยืนยันสำเร็จจึงเปลี่ยนปลายทางและปิด modal; ถ้าโหลด schema ไม่สำเร็จแสดง error ภายในและคง modal/ค่าที่ใช้อยู่; ระหว่างยืนยันปิด/ยกเลิก/Escape และกดซ้ำไม่ได้; ปิดแล้วคืน focus ให้ปุ่มจัดการปลายทาง
- หลักฐาน: `npm run build` ผ่าน; `npm run test:ci` **117/117 ใน 12 suites** รวม 6 ข้อใหม่ของ modal; `git diff --check` ผ่าน
- Edge headless QA ผ่าน: หน้าหลักแบบย่อ, staging/cancel/reopen, Escape/focus, reload เพิ่มรายการและคง applied profile, reload error/retry, schema error/retry, ยืนยันแล้วคงค่า path เดิม/ล้าง Preview, busy/close guard, ใช้รุ่นล่าสุด และ edit link ในแท็บใหม่ ไม่มี runtime exception หรือคำขอเขียน Mapping API
- ที่ viewport 1440/1280 × 1000 px: ฝั่งตั้งค่า/Preview ยังเป็น 3:2, summary สูง 147 px, modal กว้าง 1100 px สูง 826.5 px และ footer อยู่ภายใน viewport; เลื่อนฝั่งตั้งค่าแล้ว Preview อยู่ top 16 px ตามเดิม
- ตรวจด้วยข้อมูลสมมติในหน่วยความจำ browser ไม่สร้าง/แก้ไขปลายทางจริงและไม่ส่งข้อมูลไป Informs; รุ่นสุดท้ายรวม M-45 ใน Web `e6349e4` (โค้ด) + `a85f618` (styles) และ push ขึ้น `origin/develop` แล้ว
